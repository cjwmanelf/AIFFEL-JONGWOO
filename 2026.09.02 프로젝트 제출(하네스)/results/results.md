# 결과 표

`python scripts/tally.py` 가 생성한 파일. 손으로 고치지 말 것.

| 과업 | 조건 | 승인 횟수 | 완료 시간(s) | 승인 호출 지연 합(s) | 나머지 시간(s) | verify 시도 | 통과 | 토큰 |
|---|---|---|---|---|---|---|---|---|
| task1 | A | 1 | 26.2 | 6.8 | 19.4 | 1 | yes | 511661 |
| task1 | B | 0 | 20.9 | - | 20.9 | 1 | yes | 638378 |
| task2 | A | 1 | 23.5 | 2 | 21.5 | 1 | yes | 363048 |
| task2 | B | 0 | 17.1 | - | 17.1 | 1 | yes | 466267 |
| task3 | A | 1 | 25.6 | 3.6 | 22 | 1 | yes | 470616 |
| task3 | B | 0 | 19.9 | - | 19.9 | 1 | yes | 524161 |

> `승인 호출 지연 합` = 승인이 필요했던 Bash 호출들의 지연 합. 승인 대기와 명령 실행 시간이 섞여 있어 **승인 대기의 상한**으로만 읽는다. 조건 B 는 승인 호출이 없어 빈칸이다.

## 고정 조건 감사

- CLI 버전: 2.1.258 → 일치
- permissionMode: acceptEdits → 일치
- 승인 횟수 교차 확인: 1건 확인, 전부 일치

## 사전 판정식 적용

- 지지 조건: 3개 과업 중 **2개 이상**에서 `B 승인 <= A 승인 x 0.5` 이면서 `B 시간 <= A 시간 x 0.8`
- 기각 조건: 위 미달, 또는 조건 B 에 verify 실패가 하나라도 있음, 또는 B 총비용 > A 총비용 x 1.5

| 과업 | 승인 조건 | 시간 조건 | 이 과업의 판정 |
|---|---|---|---|
| task1 | 0 <= 0.5 -> O | 21 <= 21.0 -> O | 지지 방향 |
| task2 | 0 <= 0.5 -> O | 17 <= 18.8 -> O | 지지 방향 |
| task3 | 0 <= 0.5 -> O | 20 <= 20.5 -> O | 지지 방향 |

- 조건을 만족한 과업 수: **3 / 2 필요**
- 조건 B verify 실패: **0건**
- 자원 사용(토큰) A=1,345,325 / B=1,628,806 (B/A = 1.21배) -> 부작용 기각 없음

## 판정: **지지**

실행 전에 정한 식을 그대로 대입한 결과다. 기각도 실패가 아니다.
어느 과업에서 왜 줄지 않았는지가 다음 실험의 재료다.
