# 근거 카드

가설의 **출발점이 아니라 근거를 얻는 재료**다. 카드마다 등급을 숨기지 않고 적고,
"이 카드가 검증하지 않은 것"을 반드시 남긴다.

등급 표기: `[학술]` 동료평가 논문 / `[벤더]` 도구 제작사의 자체 보고 / `[공식 문서]` 도구 공식 문서

  - 확인 링크: https://docs.claude.com/en/docs/claude-code/settings
  - **접속 확인일: ____ (실행 전 본인이 열어 보고 날짜를 적을 것)**

- **측정 수치**: 없음. 문서는 **동작만** 규정하고 "얼마나 빨라지는지"는 말하지 않는다.

  - Windows/Git Bash 환경에서 `Bash(python:*)` 패턴이 실제로 매칭되는지 → **사전 점검 항목 P-1 로 이월**

## C-02 [공식 문서] 권한 모드는 승인 대상 자체를 바꾼다

- **출처**: Claude Code CLI `--permission-mode` (설치본에서 직접 확인)
- **2026-09-02 관찰 (v2.1.207)**: `claude --help` 의 `--permission-mode` 선택지는
  `acceptEdits`, `auto`, `bypassPermissions`, `manual`, `dontAsk`, `plan` 이었다.
  **`default` 는 선택지에 없었다.** 따라서 보고서에서 "default 모드"라는 표현을 쓰지 않는다.
- 🟡 **이 관찰의 출처 주의**: 위 `--help` 출력은 실험을 설계한 에이전트의 **샌드박스 환경**에서 얻었고,
  실제 실험을 돌리는 PC 와 파일시스템 뷰가 다른 것으로 확인되었다
  (같은 경로에 대해 `Test-Path` 결과가 서로 달랐다).
  **실험 PC 의 CLI 버전과 모드 목록은 아직 확인되지 않았다.**
  1회차 트랜스크립트에서 `extract_run.py` 가 뽑는 `cli_version` 과 `permissionMode` 로 확정한다.
  - 실험 PC 의 CLI: `C:\Users\cjwma\.local\bin\claude.exe` (네이티브 설치본, PATH 에 없음)
  - 확정된 버전: ____ (1회차 후 채움)
- **가설과 관련된 내용**: `acceptEdits` 는 파일 편집 승인을 자동 수락한다.
- **왜 중요한가**: 본 실험은 **Bash 실행 승인만** 조작하려 한다. 두 조건 모두 `acceptEdits` 로 고정하면
  편집 승인이 양쪽에서 0이 되어, 조작 항목이 하나로 좁혀진다.
- **이 카드가 검증하지 않은 것**: `acceptEdits` 상태에서 Bash 승인은 그대로 묻는지 → **사전 점검 항목 P-2 로 이월**

  "대기가 총 시간을 늘린다"는 방향성의 근거로만 쓴다.

### 리허설 실측 (2026-09-02, 실험 PC · CLI 2.1.226)

- **조건 A · `acceptEdits` · allowlist 비움 → `python verify.py` 가 승인을 요구했다.**
  조작 방향이 실재함을 확인. (P-1 의 A 쪽, P-4 확인)
- **조건 B 리허설은 무효.** 세션이 `acceptEdits` 로 시작했다가 도중 `auto` 로 바뀌었고
  과업 실행은 전부 `auto` 에서 일어났다. 승인이 없었던 이유가 allowlist 인지 모드인지
  구분되지 않는다. B 쪽 확정은 2회차(task2 조건 B)에서 한다.
- **모드가 바뀐 경로가 확인됐다.** 승인창의 선택지 3번이
  `Yes, and switch to auto mode` 이고, 그 위에 `auto mode handles these prompts for you`
  라는 권유 문구가 함께 나온다.
  → **하네스가 측정 대상인 마찰을 없애라고 사용자에게 권하는 구조다.**
  이것 자체가 보고서에 남길 관찰이다. 실험 절차에서는 1번 외 선택을 금지한다.
- **Bash 호출 형태**: 모든 호출 앞에 `cd "<작업폴더>" && ` 가 붙는다.
  allowlist 에 없는 `echo` 가 섞인 복합 명령도 `auto` 에서는 통과했다.
  `acceptEdits` 에서 `ls`/`cat`/`echo` 가 각각 어떻게 처리되는지는 아직 미확인.

### 실행 방식에 관한 실측 기록 (2026-09-02)

- **중첩 헤드리스 실행은 불가능하다.** 다른 Claude Code 세션 안에서 `claude -p` 를 부르면
  `Failed to authenticate: OAuth session expired and could not be refreshed` 로 즉시 실패한다.
  따라서 이 실험은 **사람이 대화형 세션 6회를 직접 실행**해야 한다. 자동 배치로 대체할 수 없다.
- **설계 에이전트의 도구 환경과 실험 PC 는 파일시스템 뷰가 다르다.** 같은 절대 경로에 대해
  한쪽은 파일이 있다고, 다른 쪽은 없다고 답했다. 그래서 실행 환경에 관한 사실
  (CLI 위치·버전·설정 파일 존재 여부)은 **실험 PC 의 셸 출력만 근거로 삼는다.**
  설계 쪽에서 얻은 값은 참고용으로만 남기고 보고서의 근거로 쓰지 않는다.
- **승인 이벤트는 트랜스크립트에 남지 않는다.** `~/.claude/projects/**/*.jsonl` 에는
  `permissionMode`, 툴 호출 원문, 호출별 타임스탬프, 토큰은 남지만 "승인창이 떴다"는 기록은 없다.
  그래서 `scripts/extract_run.py` 는 승인 횟수를 **측정하지 않고 규칙으로 유도**하며,
  사람이 실제로 센 횟수를 교차 확인용으로 따로 적는다.

P-1 이나 P-2 에서 규칙 문법을 고쳐야 했다면, **고친 내용을 여기에 적고 두 조건 모두에 동일하게 적용한 뒤**
리허설부터 다시 시작한다.
