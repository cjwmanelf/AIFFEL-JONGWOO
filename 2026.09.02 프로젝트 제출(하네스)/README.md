# 하네스 개선 실험 01 — 권한 규칙(allowlist) 범위

모두의연구소 `AI Agent 파해치기_Agt1` / 11강 「논문 가설을 내 개선 실험으로 바꾸기」 제출물.

내가 실제로 쓰는 하네스(**Claude Code**)에서 겪은 불편 하나를 반증 가능한 가설로 바꾸고,
**한 항목만 조작하는** 실험으로 설계했다. 전체 보고서는 [`experiment-01.md`](experiment-01.md).

- **불편**: Python 과업에서 `python verify.py` 같은 실행 명령마다 승인창이 떠서, 편집→실행→확인 루프가
  매번 사람의 반응을 기다리며 멈춘다.
- **조작한 하네스 기능**: 프로젝트 권한 규칙 `permissions.allow` 의 범위. **이것 하나만** 바꾼다.
- **현재 상태**: **6회 실행 완료.** 판정 **지지** — 단, 인과 설명은 약하다 (아래 3절)

---

## 1. 가설

> Claude Code 의 프로젝트 권한 규칙에 그 과업에서 반복되는 실행 계열 명령(`python`, `python -m unittest` 등)을
> 미리 등록하면, 등록하지 않은 조건에 비해 같은 과업의 **승인 프롬프트 횟수와 벽시계 완료 시간이 함께** 줄어든다.

반증 조건: 승인 횟수가 줄었는데 완료 시간이 줄지 않거나 늘면 **기각**.
조건 B 에서 과업 검증에 실패한 과업이 하나라도 있으면 **기각**.

근거는 `[공식 문서]`(동작 규정)와 `[벤더]`(권장)뿐이고 **속도에 대한 수치 근거는 어느 카드에도 없다.**
그 빈칸이 이 실험의 이유다. 등급별 카드: [`evidence/evidence-cards.md`](evidence/evidence-cards.md)

## 2. 실험 설계

| 구분 | 내용 |
|---|---|
| 고정 | 같은 버전·모델 / 같은 fixture 3개 / 같은 요청 문장 / 매회 새 세션·새 폴더 / 양 조건 모두 `--permission-mode acceptEdits` |
| 조작 | `.claude/settings.json` 의 `permissions.allow` 만 — **A(대조)** 빈 목록 vs **B(처치)** 실행 계열 8개 등록 |
| 측정 | 승인 횟수 / 완료 시간 / 승인 대기 시간 / 순수 실행 시간 / 검증 시도 수 / 통과 여부 / 비용·토큰 |
| 사전 판정식 | 3개 과업 중 **2개 이상**에서 `B 승인 ≤ A × 0.5` **이면서** `B 시간 ≤ A × 0.8` → **지지**. 미달·검증 실패·비용 1.5배 초과 → **기각**. 보류 없음 |

판정식은 [`scripts/tally.py`](scripts/tally.py) 상단 상수에 코드로 박아 두었다.
결과를 보고 기준을 고치는 일을 막기 위해서다.

고정 과업 3종(모두 표준 라이브러리만 사용, 채점기 `verify.py` 포함):
`parse-log` / `refactor-util` / `fix-failing`.

예상 반론 5개와 각각의 통제 조건은 보고서 [4절](experiment-01.md#4-실험-설계)에 표로 정리했다.

## 3. 결과

6회 전부 실행 완료 (2026-09-02). 고정 조건 감사 통과: CLI 2.1.258 단일, `acceptEdits` 단일, 6회 모두 검증 통과.

| 과업 | 조건 | 승인 | 완료 시간(s) | 승인 호출 지연 합(s) | 나머지 시간(s) | 토큰 |
|---|---|---|---|---|---|---|
| task1 | A | 1 | 26.2 | 6.8 | 19.4 | 511,661 |
| task1 | B | 0 | 20.9 | — | 20.9 | 638,378 |
| task2 | A | 1 | 23.5 | 2.0 | 21.5 | 363,048 |
| task2 | B | 0 | 17.1 | — | 17.1 | 466,267 |
| task3 | A | 1 | 25.6 | 3.6 | 22.0 | 470,616 |
| task3 | B | 0 | 19.9 | — | 19.9 | 524,161 |

**사전 판정식: 지지** (3/3 과업). 조작은 승인 횟수를 확실히 줄였다 (과업마다 1 → 0).

**그런데 인과 설명은 약하다.** 시간 조건은 마진 0.06초(task1), 0.58초(task3)로 겨우 통과했고,
승인 지연을 뺀 "나머지 시간"에서 이미 B 가 평균 1.7초 빨랐다 — 가설이 설명하지 못하는 차이다.
20초대 과업에서 회차 간 변동폭이 조작 효과와 같은 크기이고, 과업당 표본은 1회다.
설계 때 적어 둔 R-2 통제가 발동한 것이며, 자세한 검토는
[8절 원인 검토](experiment-01.md#8-원인-검토--불편의-진짜-원인이-이-하네스-기능이었나)에 있다.

전체 표와 판정 과정: [`results/results.md`](results/results.md) (`python scripts/tally.py` 가 생성)

## 4. 다시 검토할 조건

- 권한 규칙 문법이나 기본 권한 모드가 바뀌었을 때. **실측만으로도 리허설 사이에 CLI 가
  2.1.226 → 2.1.258 로 자동 업데이트됐다.**
- 하네스가 자체 통과시키는 명령 목록이 바뀌었을 때. 조작의 실제 범위가 함께 바뀐다.
  이번에 조건 B allowlist 8개 중 실제로 작동한 것은 python 계열 3개뿐이었다.
- 과업 유형이 바뀌었을 때. 특히 승인이 여러 번 발생하거나 실행 시간이 분 단위인 과업
- 승인 응답자가 바뀌거나 3초 응답 규약이 지켜지지 않을 때
- 반복을 붙인 2회차에서 시간 조건의 방향이 뒤집힐 때. 지금 마진은 0.06초짜리도 있다.

미확인으로 남긴 항목(완료 시간 단축의 실재성, 승인 대기의 순수 길이, 하네스 자체 통과 명령의
전체 목록, `[학술]` 카드 원문, 순서 효과 잔여분)은 보고서 마무리 기록에 그대로 적어 두었다.

```
agent-harness-exp-01/
├─ README.md                  이 파일 (가설 / 설계 / 결과 / 다시 검토할 조건)

│  ├─ task1-parse-log/        sample.log, TASK.md, verify.py

├─ scripts/
│  ├─ new_run.py              실행 1회분 폴더 생성 (픽스처 복사 + 조건 설정 + 기록지)
│  └─ tally.py                기록 집계 + 사전 판정식 적용
├─ results/
│  ├─ record-template.md      회차 기록지 원본
│  └─ results.md              tally.py 가 생성
```

## 실행 방법

```bash
python scripts/new_run.py --task 1 --cond A --seq 0 --rehearsal
```

먼저 리허설로 사전 점검 P-1~P-4 를 확인한다. 그다음 [`protocol/RUNBOOK.md`](protocol/RUNBOOK.md)
순서대로 6회 실행하고 각 `runs/*/record.md` 를 채운 뒤:

```bash
python scripts/tally.py
```

픽스처가 멀쩡한지 확인하려면 (셋 다 처음에는 FAIL 이 정상):

```bash
python fixtures/task3-fix-failing/verify.py
```
